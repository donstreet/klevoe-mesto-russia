# 09. Правила разработки и работы с репозиторием

## Назначение
Этот репозиторий — чистая основа нового всероссийского проекта. Он не является зеркалом старого приложения и не подключён к Production. Код и данные переносятся из прежних проектов только после аудита и отдельного решения.

## Ветвление
- main — стабильная интеграционная ветка.
- feature/<short-name> — отдельная функция.
- fix/<short-name> — исправление.
- docs/<short-name> — документация.

Изменения в main проходят проверку. Для существенных изменений предпочтителен Pull Request с описанием, тестами и оценкой риска.

## Обязательный порядок работы
1. Изучить существующую структуру и контракты.
2. Сформулировать задачу и критерии приёмки.
3. Проверить влияние на пользователей, регионы, API и БД.
4. Сделать минимальное изолированное изменение.
5. Добавить/обновить тесты и документацию.
6. Проверить lint, typecheck, тесты и сборку.
7. Развернуть Preview и пройти QA.
8. Получить отдельное разрешение на Production-релиз.
9. Выпустить, проверить и при необходимости откатить.

## Правила безопасности публичного репозитория
Никогда не коммитить API-ключи, токены, пароли, SSH-ключи, cookie, реальные .env, дампы БД, пользовательские выгрузки, персональные данные, переписки, номера телефонов, платёжные сведения, приватные URL и внутренние адреса сервисов.

Использовать .env.example только с фиктивными именами переменных и пустыми/примерными значениями. При обнаружении секрета в истории Git считать его скомпрометированным: отозвать/заменить, затем отдельно очистить историю.

## Перенос старого кода
Старый репозиторий starobeshevo-fishing-app содержит раннюю Telegram Mini App и статические данные конкретного водоёма. Не переносить его целиком как основу всероссийской архитектуры. Сначала провести аудит компонентов, данных, лицензий, зависимостей и пригодности. Полезные элементы переносить отдельными PR с указанием происхождения.

## Definition of Done
Задача завершена, когда критерии приёмки выполнены, тесты пройдены, документация обновлена, Preview проверена, риски и ограничения записаны, а Production-релиз одобрен отдельно.
