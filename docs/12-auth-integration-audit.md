# 12. Аудит авторизации перед подключением Telegram и Яндекс ID

Дата проверки: 2026-11-18

## Вывод

Новый Next.js Preview на Vercel пока является отдельным демонстрационным приложением. В нём нет авторизации, базы данных, OAuth-маршрутов и переменных окружения. Подключать OAuth как независимую систему пользователей нельзя: это создаст риск появления дублирующих аккаунтов и потери связи с действующими профилями.

Источником истины для существующих пользователей пока остаётся действующее Express-приложение на сервере `137.22.151.247`.

## Обязательные правила реализации

1. Не создавать новый пользовательский аккаунт автоматически только по факту успешного OAuth.
2. Сначала связать подтверждённый внешний идентификатор провайдера с уже существующим `userId` через авторизованную сессию пользователя.
3. Для входа через провайдера без предварительной сессии использовать отдельный безопасный сценарий восстановления/сопоставления; не сопоставлять аккаунты только по непроверенному имени или отображаемому nickname.
4. Сохранять существующие ID пользователей, пароли, роли, премиум-доступы, публикации и связи.
5. Не переносить действующие session tokens в новый сервис и не выводить их в логи.
6. Секреты хранить только в серверном хранилище. Не передавать их в клиентский код, Git, логи или чат.
7. Сначала реализовать и тестировать всё на изолированном Preview. Production и действующие JSON-файлы не изменять.
8. Не менять настройки BotFather и OAuth-провайдеров, пока callback и конечная схема входа не проверены на стороне приложения.

## Следующий безопасный этап

Сначала согласовать архитектурную границу: Next.js Preview должен работать с существующим Preview Express API как с источником пользователей и сессий либо требуется отдельная миграция данных в новую БД. До этого не создавать вторую независимую систему учётных записей и не включать OAuth callback, который не сможет безопасно связать пользователя с существующим `userId`.
